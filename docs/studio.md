# Studio process

The CEO gives features. The TPO turns each one into acceptance criteria, picks the roles it needs, and runs independent work in parallel.

## Roles

- **TPO**: breaks down the feature, sequences the roles, tracks status, reports back.
- **Creative head**: concept, art direction, mood and palette.
- **Storyteller**: researches history and mythology, writes screenplays and event data.
- **UX designer**: flows, screens, controls, accessibility.
- **Principal engineer**: architecture, tech choices, performance budget, reviews.
- **Developer**: builds the feature and runs it.
- **QA**: test plan, test runs, bug reports, release call.

## Typical order

Creative head first, then Storyteller and UX designer in parallel, then Principal engineer, then Developer, with QA writing the test plan alongside development and testing after.

## Two work lines

- **Build line**: the engine, then the current mission.
- **Content line**: works one mission ahead, delivering screenplay, event data and layout to a fixed handoff format.

Neither line edits the other's files. QA gates anything moving to done.

## Standards

WCAG 2.2 AA, mobile first, and browser performance budgets apply to every feature. Automated checks do not guarantee legal ADA compliance, so plan a third-party accessibility audit before a public launch.
